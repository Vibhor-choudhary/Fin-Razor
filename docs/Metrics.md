# Success Metrics

## Overview

All metrics are computed on a **synthetic batch** of sessions generated by the local seed script. The batch is split into two groups:

- **Control group** — sessions processed without the agent (baseline).
- **Treatment group** — sessions processed with the Upsonic agent active.

---

## Metric Definitions

### 1. Baseline Conversion Rate

```
baseline_conversion = (sessions that succeeded without agent) / (total control sessions)
```

- Sessions are classified as "succeeded" if their `final_status = 'succeeded'`.
- This establishes the natural conversion rate before any AI intervention.

### 2. Agent Conversion Rate

```
agent_conversion = (sessions that succeeded with agent active) / (total treatment sessions)
```

- Sessions are classified as "succeeded" if `final_status = 'succeeded'` after an agent intervention (or despite the agent abstaining).
- **Target:** agent_conversion ≥ baseline_conversion + 15 percentage points.

### 3. Recovery Lift

```
recovery_lift = agent_conversion - baseline_conversion
```

- The raw improvement attributable to the agent's interventions.

### 4. False-Positive Cost

A "false positive" is an intervention applied to a session that **would have converted on its own** without any help.

```
false_positive_rate = (interventions on self-converting sessions) / (total interventions applied)
```

**Cost model:**
- Each false-positive intervention = 1 unit of "annoyance cost" (user shown a prompt they didn't need).
- For demo purposes, we assign a token cost of ₹5 per false positive (hypothetical merchant review overhead).
- Total false-positive cost = false_positive_count × ₹5.

**Target:** false_positive_rate < 20%.

### 5. Abstain Rate

```
abstain_rate = (at-risk sessions where agent chose "none") / (total at-risk sessions)
```

- Agent should abstain when confidence score < 0.6 threshold.
- An abstain rate between **10–30%** is healthy — it confirms the agent is not blindly intervening.
- Abstain rate > 50% suggests the detection signal is too weak.

### 6. Unresolvable Session Rate

```
unresolvable_rate = (sessions marked "unresolvable" due to API/agent error) / (total sessions)
```

- Used to verify the graceful failure scenario is captured correctly.
- **Expected in demo:** ≥ 1 session ends up here intentionally.

### 7. Total Modeled Recovery

- **Verified Sandbox Recovery**: Revenue recovered via actual successful Hyperswitch sandbox retry payments.
- **Simulated Nudge Recovery**: Revenue recovered via deterministic simulated customer behavior (nudge converts).
- **Total Modeled Recovery**: Combined sum of verified sandbox payments and simulated modeled nudges.

---

## How Metrics Are Computed on Synthetic Batch

1. **Seed script** generates N sessions (suggested: N = 100) with randomised cart values, failure patterns, and pre-assigned "ground truth" outcomes (would have converted vs would not).
2. **Control run:** All sessions processed without agent. Final statuses recorded. `baseline_conversion` computed.
3. **Treatment run:** Same sessions (or fresh batch of same distribution) processed with agent active. Interventions applied. Final statuses recorded. `agent_conversion` computed.
4. Ground-truth labels are used to identify false positives.
5. Backend `/metrics` endpoint aggregates all of the above and stores a `metrics_snapshot` row.
6. Merchant console UI fetches `/metrics` and displays the comparison table.

### Honesty Note (Sandbox Simulation)
> [!IMPORTANT]
> - **Real Sandbox Transactions:** All Hyperswitch payment creations, confirmations, decline handling, status updates, and raw API payloads are real sandbox transactions processed over the live Hyperswitch Sandbox API.
> - **Simulation Limitations:** The 100-session dataset, customer responses to nudges, and retry outcome scenarios are programmatically simulated to evaluate bounded recovery agent behavior; they are not claims about actual production customer conversion rates.
